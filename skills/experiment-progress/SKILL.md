# 实验进度

将长实验接入本机面板，并保留已有静默跟进。使用本 skill 目录中的 `scripts/experiment_progress.py`。Python 3.9+，无第三方依赖。以 macOS 实测为准；Linux 待验证，Windows 暂不支持（使用 `fcntl` 和 `ps`）。面板及数据仅在本机，服务按需启动；不是操作系统级进程自动探测器。

## 启动前

- 先检查实验入口、任务清单、并发方式和日志格式。复用已有状态输出；不改模型、随机种子、算法、求解时限、调度顺序或结果判定。
- 定义一个实验 ID 对应的工作单元，如“算法×实例×参数×种子”。ID 优先用 `/` 分隔各参数（如 `bo01/30-10-2/seed0`），或在计划中给出 `params`，ETA 会据此让相同取值的任务互相参照。生成已知任务清单，重试沿用同一 ID，避免重复计数。总量未知时省略，不能从完成文件数量猜总量。
- 优先让已有驱动程序调用下面的 `task()`；若日志已经明确记载每个实例的开始、结束及结果，可写一个只读日志适配器，调用 `report()`。只根据原日志明确状态上报，支持 `started_at` / `ended_at` Unix 秒时间戳。日志重复读取不会重复计数；任务结束事件缺开始时间时不纳入 ETA 样本。
- 仅接入无任务事件的命令也可显示进程、日志和计时，但必须说明实验计数尚未接入。不能将整个批次登记为“一次实验”冒充内部实例计数。

## Python 驱动程序接入

将 skill 的 `scripts/` 目录加入该驱动的模块搜索路径，然后在原有任务边界加入以下记录；原先已有可靠结果判断时优先直接调用 `report()`。

```python
from experiment_progress import task, report

with task("algorithm-instance-parameter-seed", group="同类规模组"):
    result = run_existing_experiment()
    # 如果原驱动把失败编码为返回值，应沿用其判定并报告 failed，不能仅按无异常认定成功。
```

`task()` 在进入时记录 running，正常退出时记录 succeeded，出现异常时记录 failed 并重新抛出原异常。监控写入失败只输出警告，不改变实验的异常传播。对返回状态码、超时结果等情况用 `report(task_id, "running")` 和 `report(task_id, "succeeded"或"failed")`，由原实验判定规则决定结果；求解器达到时限可能是有效实验结果，不能一律归为运行失败。进度记录包在整个单次试验外，保持原求解计时区间。

多进程中每个 worker 可以独立报告；SQLite 事务负责合并。`EXPERIMENT_PROGRESS_RUN` 和 `EXPERIMENT_PROGRESS_HOME` 由启动器传给子进程。不支持通过网页启动、终止或重试实验。

## 命令

以下 `EP` 按会话技能目录中的实际安装位置填写，不假设固定用户目录。保持完整引用；不要修改 HOME 或 CODEX_HOME。

```sh
EP="/absolute/path/to/experiment-progress/scripts/experiment_progress.py"
python3 "$EP" launch --name "参数对比实验" --cwd "/absolute/project" --plan "/absolute/project/work/plan.json" -- python3 -u driver.py
```

计划格式：`[{"id":"case-001","group":"small"},{"id":"case-002","group":"large"}]`；可选 `"params":{"algo":"bo01","inst":"30-10-2","seed":0}`（至多 20 项，值为字符串或数值），只用于 ETA。组名中的规模数字（如 `n=30`）也会被用来外推尚未开始的组。总数取计划长度；没有逐项清单时可改用 `--total 120`，尚未报告的任务按当前唯一组或总体样本粗估。已知分组时仍应提供完整计划。

`launch` 后台启动前台实验命令，返回 `run_id`、本机 `url` 和数据位置。必须让被启动的驱动等待全部 worker 结束，不能再用 `nohup`、`&` 或只提交工作后就退出。保留原工作目录、解释器、环境及参数；不要为展示进度另跑一份实验。标准输出和错误写入该轮日志，父命令退出后实验继续运行。计算机休眠会影响实际运行及 ETA。

启动后用 `open_in_codex` 打开返回 URL；工具不可用时用浏览器打开，或 `dashboard --open`。向用户提供面板链接，用 `status --run RUN_ID --brief` 检查一次确认已接入（几行摘要，需要完整字段时去掉 `--brief`）。自动打开失败不等于实验启动失败，不要重复 launch。

```sh
python3 "$EP" dashboard --open
python3 "$EP" status --run RUN_ID --brief
python3 "$EP" list
python3 "$EP" backtest
python3 "$EP" event running --run RUN_ID --task case-001 --group small
python3 "$EP" event succeeded --run RUN_ID --task case-001
python3 "$EP" attach --name "已有实验" --pid PID --cwd "/absolute/project" --total 120 --log "/absolute/project/run.log"
```

`attach` 只观察已有 PID，以其原始启动时间计时；它无法取得原进程退出码，不自动把退出判为成功。不会读取或解析任意日志中的实验次数，必须另接明确的任务事件或只读适配器。显示日志限最后约 8 KB，运行中与失败明细各限 30 项，轮次列表限最近 50 轮；完整状态仍保存在数据库。

## 面板

页面包含轮次侧栏、读数区（已结束数、耗时、预计剩余的点估计与范围及其依据强度、近期节奏）、任务矩阵（每格一个实验，组内按开始时间排列，未开始的排在后面；可按 ID 搜索、悬停或方向键查看）、完成曲线与启发式预测范围、分组耗时分位数、日志和记录位置。可选浏览器结束提醒、亮暗主题和动效开关；系统设置减少动态效果时自动关闭动画。

面板服务启动时载入页面，更新本 skill 后已开着的旧服务仍显示旧页面。需要切换时运行 `python3 "$EP" dashboard --restart`：只替换面板服务，链接和 token 不变，不影响 `_supervise` 与实验进程。数据库结构保持向后兼容，正在运行的旧版本进程可继续写入；不要为了切换页面而改表或重启实验。

有可比的历史耗时、试跑记录或用户给出的预估时，可在 `launch` / `attach` 的实验命令分隔符 `--` 前加 `--estimate-seconds 单次秒数 --estimate-source "依据"`，让首个实验完成前也有 ETA。这里填单次实验的耗时，不是整批时间；不能把求解时限直接当平均耗时。优先复用当前项目、相同设置的记录，不自动混入其他项目历史，也不为估时另跑实验。

已启动轮次可随时补入预估，无须重启实验：`python3 "$EP" set-prior --run RUN_ID --seconds 单次秒数 --source "依据"`。需要区分组时加 `--group 组名`；省略表示所有尚无同组样本的组。预估只在缺少同组计时样本时使用，不能编造依据。完全无依据时保持未知，直到出现首个有效样本。

## 数值与异常

- 成功和失败分开，已结束包含两者。重复结束事件幂等；同一任务重试要先重新报告 running。计划内未报告任务保留为等待/未报告。退出码 0 不足以证明所有实验完成。
- ETA 给出点估计和范围，随证据逐步更新。同组有 1 个计时成功样本即可估计（1–2 个为“初步估计”，范围放宽到 0.5–2 倍）；单项耗时取同组最近至多 120 个成功样本的近期加权平均（半衰期 30 个），失败任务按其自身耗时和失败比例计入，不混入成功耗时。
- 任务参数（计划 `params`，或 ID 中 `/` 分隔的各段；取值从不重复的段不用）按对数加性效应校正单项耗时，相同取值的已完成任务偏快或偏慢，剩余同取值任务随之调整；少见取值向 0 收缩，从未出现的取值按该参数最近任务的效应处理。
- 没有同组样本的组依次使用：已提供的分组或全局预估（“初始预估”，0.5–2 倍，注明来源）；组名只差一个数字的同族组中至少 2 组有样本时按幂律外推（“规模外推”）；与组名共享词元最多的组（“相近组借用”）；全部组平均（“跨组粗估”）。出现同组样本后自动替换。
- 在跑任务的剩余时间取同组中比它已运行更久的样本的平均剩余；超过几乎所有样本时按已运行时间的一半估计并标注“动态粗估”。再按当前并发数和等待清单贪心排队得到点估计；范围由组内分块耗时的漂移、单项波动和推算方式合成，是启发式范围，不是置信区间或完成时限。有依赖、并发变化、机器持续变慢或后续配置系统性更快/更慢时偏差可能较大。
- `backtest [--run ID]` 只读回放已结束轮次，报告各时点实际剩余落在范围内的比例、点估计中位偏差和范围宽度，用来检验 ETA，不代表未来实验的准确度保证。
- 未知总量、没有运行中任务、监测信号中断，或完全没有有效计时成功样本且未提供预估时，ETA 保持未知并说明原因。缺起止时间或零耗时记录不作为耗时样本。不要把实例完成比例解释为耗时比例，也不要把最优性 gap 转成时间进度。
- 独立监测进程每 2 秒写心跳；12 秒无信号标记状态待核验。网页读取失败保留最后数据并提示。观察不到更新不等于实验失败。
- 保留已有静默跟进，仍按用户原有通知偏好处理完成、失败及需要操作的状态；不为刷新数字增加模型轮询或重复的自动跟进。

默认状态目录为 `~/.codex/experiment-progress/`，包含数据库、轮次日志和服务信息。测试可设置 `EXPERIMENT_PROGRESS_HOME` 为隔离目录。全局安装只改变进度接入工作流，不扩大科研代码修改或对外操作的授权。

验证：`python3 scripts/test_monitor.py`。演示任务：用 `launch --demo --total 15 --name "面板验证" -- python3 /absolute/skill/scripts/demo.py`；演示分两组，包含一个故意失败的任务和一次同 ID 重试，预期成功 14 项、失败 1 项。
